# Cloudflare R2 전체 에셋 이전 설계

## 목적

React 애플리케이션과 무거운 정적 에셋의 배포를 분리한다. 브라우저는 GLB, 이미지, 오디오, 영상과 폰트를 Vercel이 아닌 Cloudflare R2에서 직접 내려받는다.

## 현재 상태

- `public/assets`에는 165개, 약 228.02 MiB의 파일이 있다.
- `src/assets`에는 17개, 약 36.43 MiB의 파일이 있다.
- 합계는 182개, 약 264.45 MiB다.
- 이 중 Git이 추적하는 파일은 89개, 약 181.37 MiB다.
- Git에서 제외된 로컬 파일은 93개 경로, 약 83.07 MiB다.
- `src/assets`와 `public/assets`에 내용이 같은 중복 파일이 있다.
- `subway.wepm`처럼 실제 파일과 맞지 않는 코드 경로가 있다.
- `Gamza_cycle.glb` 한 개는 PoC를 통해 R2 제공과 CORS 동작을 검증했다.

## 목표

- 코드가 실제로 요청하는 모든 필수 에셋을 목록으로 남긴다.
- 각 파일의 R2 객체 키, 크기, 해시와 Git 추적 여부를 확인할 수 있게 한다.
- 중복과 사용하지 않는 파일을 구분해 필요한 파일만 R2에 올린다.
- R2 객체 키는 기존과 같은 `assets/<종류>/<파일명>` 구조를 유지한다.
- JavaScript와 JSX는 `getAssetUrl()`을 통해 주소를 만든다.
- `public/index.html`과 CSS도 같은 환경변수 기반 주소를 사용한다.
- 새로 clone한 저장소에 로컬 에셋이 없어도 빌드와 실행이 가능하게 한다.
- 운영 페이지의 에셋 요청에서 404와 CORS 오류가 발생하지 않게 한다.

## 제외 범위

- 이번 작업에서 커스텀 도메인을 연결하지 않는다.
- 이미지·GLB 자체의 압축이나 화질 조정은 하지 않는다.
- 장면별 지연 로딩 구조를 새로 설계하지 않는다.
- 비공개 파일, 서명 URL, Cloudflare Worker를 추가하지 않는다.
- 업로드 자격 증명을 저장소나 프론트엔드 환경변수에 넣지 않는다.

## 선택한 방식

하나의 PR 안에서 다음 단계를 순서대로 통과한다.

1. **인벤토리 작성**: 코드 참조와 실제 파일을 비교한다.
2. **R2 업로드**: 필요한 파일만 기존 디렉터리 구조 그대로 올린다.
3. **경로 전환**: 모든 실행 경로가 공통 기본 URL을 사용하게 한다.
4. **검증**: 빌드, 자동 검사, 로컬 브라우저와 배포 환경을 확인한다.
5. **정리**: R2에서 정상 제공되는 파일만 저장소와 로컬 배포 묶음에서 제거한다.

각 단계는 독립된 커밋으로 남긴다. 문제가 생기면 어느 단계에서 깨졌는지 쉽게 찾고 되돌릴 수 있다.

## 인벤토리 설계

인벤토리는 사람이 손으로 파일명을 복사한 문서가 아니라 검사 가능한 데이터로 관리한다. 각 항목에는 다음 정보를 담는다.

- 로컬 원본 경로
- R2 객체 키
- 파일 종류
- 바이트 크기
- SHA-256 해시
- Git 추적 여부
- 코드 참조 여부
- 이전 상태

검사 스크립트는 다음 오류를 실패로 처리한다.

- 코드가 참조하지만 원본 파일이 없음
- 서로 다른 원본이 같은 R2 객체 키를 사용함
- 필수 항목의 해시나 크기가 비어 있음
- 코드에 변환되지 않은 `/assets/...` 하드코딩이 남아 있음

주석 속 경로와 사용하지 않는 후보는 별도 목록으로 분리한다. 자동 삭제하지 않고 사람이 확인한 뒤 제외한다.

## URL 구성

JavaScript와 JSX에서는 기존 `getAssetUrl()`을 사용한다.

```jsx
const modelUrl = getAssetUrl("/assets/models/Bakery.glb");
```

동적으로 파일명을 조합하는 코드도 마지막에 `getAssetUrl()`을 한 번 거친다.

```jsx
const modelUrls = names.map((name) =>
  getAssetUrl(`/assets/models/${name}.glb`),
);
```

`public/index.html`은 Create React App이 빌드할 때 치환하는 `VITE_ASSET_BASE_URL` 값을 사용한다. CSS 배경 이미지는 JavaScript가 공통 헬퍼로 만든 CSS 사용자 지정 속성에 넣고, CSS에서는 `var(...)`로 읽는다. 이렇게 하면 R2 주소를 여러 파일에 직접 복사하지 않아도 된다.

기본 URL이 비어 있으면 `getAssetUrl()`은 기존 `/assets/...` 주소를 반환한다. 이는 개발 중 임시 복구용이다. 전체 이전이 끝난 뒤 새 clone 검증에서는 R2 기본 URL을 반드시 사용한다.

## 업로드와 무결성

- 업로드는 브라우저 수동 선택이 아닌 R2의 S3 호환 API를 이용해 반복 가능한 방식으로 수행한다.
- 로컬 비밀키는 셸 환경이나 사용자 자격 증명 저장소에서만 읽는다.
- 각 객체는 올린 뒤 `HEAD` 또는 `GET`으로 상태 코드, 크기와 `Content-Type`을 확인한다.
- 인벤토리의 SHA-256 해시로 원본과 업로드 대상을 대조한다.
- 기존 `Gamza_cycle.glb`도 같은 검증 절차에 포함한다.

## 오류 처리와 되돌리기

- 업로드가 일부 실패하면 코드 경로를 전환하지 않는다.
- 코드 경로 전환 뒤 오류가 생기면 해당 커밋을 되돌리고 기존 Vercel 경로를 사용한다.
- R2 객체 삭제는 모든 검증이 끝난 뒤에도 이번 작업에서 하지 않는다.
- 기존 로컬 에셋은 R2와 운영 배포 검증이 끝나기 전까지 제거하지 않는다.
- 공개 권한은 읽기만 허용한다. CORS는 기존처럼 허용된 origin의 `GET`, `HEAD`만 받는다.

## 검증 기준

### 자동 검증

- URL 헬퍼와 인벤토리 검사 테스트 통과
- `npm run test:ci` 통과
- `npm run build` 통과
- 빌드 결과에 이전 대상 대용량 파일이 포함되지 않음
- 실행 코드에 변환되지 않은 에셋 경로가 남지 않음

### 브라우저 검증

- 첫 화면 영상과 가이드 이미지 표시
- 플레이어와 각 장면의 GLB 표시 및 애니메이션 재생
- 장면별 이미지와 오디오 재생
- 엔딩 영상 재생
- 모든 이전 대상 요청이 `r2.dev`로 전송됨
- 404, CORS, GLTF 파싱 오류가 없음

### 새 clone 검증

추적되지 않은 로컬 에셋이 없는 깨끗한 작업 공간에서 의존성을 설치하고 빌드한다. 이 환경에서 페이지가 R2 에셋만으로 동작해야 한다.

## 완료 후 구조

```text
Vercel
└─ React, HTML, CSS, JavaScript

Cloudflare R2
└─ assets
   ├─ models
   ├─ images
   ├─ audio
   ├─ video
   └─ fonts
```

## 후속 작업

- 모든 성능 개선 작업이 끝난 뒤 이슈 #16에서 `r2.dev`를 `assets.<domain>` 형태의 커스텀 도메인으로 바꾼다.
- URL은 환경변수로 관리하므로 후속 전환 때 애플리케이션 코드는 바꾸지 않는다.
- 압축, 장면별 지연 로딩과 캐시 정책 개선은 별도 성능 이슈에서 측정값을 기준으로 진행한다.
